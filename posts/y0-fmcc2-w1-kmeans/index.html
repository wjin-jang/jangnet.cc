Y0/FMCC2/W1 – K-means Clustering

October 20, 2025 · UAL, Year 0, reflection, FMCC2

K-means Clustering is an algorithm that organises points into space into an arbitrary amount of clusters. One application of this is to extract a colour palette from an image.

The K-means algorithm is as such:

  1. Place centroids randomly in space.
  2. Assign each point to its closest centroid.
  3. Move centroid to the average position of its cluster
  4. Repeat until the points stop moving (or move very little) or until the maximum number of iterations is reached.

I created a Cluster object to make this easier.

class Cluster {
  constructor(pos) {
    this.position = pos;
    this.points = [];
  }

  move() {
    if (this.points.length === 0) return 0;

    let sum = createVector(0, 0, 0);
    for (let p of this.points) {
      sum.add(p);
    }
    let newpos = p5.Vector.div(sum, this.points.length);
    let movement = p5.Vector.dist(newpos, this.position);
    this.position = newpos;

    return movement;
  }
}

Extraction

I extract all the unique colours from the image.

let colourSet = new Set();
for (let x = 0; x < img.width; x++) {
	for (let y = 0; y < img.height; y++) {
		let pixel = img.get(x, y);
		let key = `${pixel[0]},${pixel[1]},${pixel[2]}`;
		if (!colourSet.has(key)) {
			colourSet.add(key);
			colours.push(color(pixel[0], pixel[1], pixel[2]));
		}
	}
}

I use a set so there are no duplicates. Since sets use a hash table, it's much faster than an array.

Initialisation

I initialise the clusters. I choose a random colour from the image. This tends to give much cleaner results since the clusters won't be too far from other points.

for (let i = 0; i < k; i++) {
  let randIndex = floor(random(colours.length));
  clusters.push(new Cluster(colours[randIndex].copy()));
}

Main Loop

I then run the K-means algorithm

let iteration = 0;
let iterationsMax = 65536;
let movement = 999;

while (movement > 0.001 && iteration < iterationsMax) {
  movement = 0;

for (let i in clusters) {
  clusters[i].points = [];
}

for (let i in colours) {
  let closest = 0;
  let smallestDistance = Infinity;
  for (let j in clusters) {
	let distance = colours[i].dist(clusters[j].position);
	if (distance < smallestDistance) {
	  smallestDistance = distance;
	  closest = j;
	}
  }
  clusters[closest].points.push(colours[i]);
}

for (let i in clusters) {
	movement += clusters[i].move();
}

iteration++;
}

The images and their extracted palettes are displayed. (Note: I resize the original img variable to speed up the palette extraction. I use fullimg to store the image pre-crushing)

function draw() {
  background(220);
  image(fullimg, 0, 0);
  
  let totalParts = 31;
  let unit = height / totalParts;
  let swatchSize = unit * 5;
  let gap = unit;

  for (let i = 0; i < clusters.length; i++) {
    let rgb = clusters[i].position;
    fill(rgb[0], rgb[1], rgb[2]);
    noStroke();
    let y = gap + i * (swatchSize + gap);
    rect(10, y, swatchSize, swatchSize);
  }
}

Perceptual Colour Space and OKLAB

So far, I have placed these images in a RGB colour space. RGB doesn't map well with perceived colour difference. We can massively upgrade this algorithm by using OKLAB. A colour space where euclidean distance matters for how perceptually similar colours are.
